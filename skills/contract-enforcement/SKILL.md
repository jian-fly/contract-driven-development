# Contract Enforcement（契约强制执行守卫）

> 优先级最高（仅低于 SECURITY.md 红线）。与其他 Skill 或用户临时指令冲突时以此为准。

## 0. 强制触发（MUST INVOKE FIRST）

以下任务开始前必须调用本 Skill：新增/修改功能、修复 Bug、编辑/创建/删除代码文件、重构/迁移/架构调整、编写或修改测试、接口/数据/模块结构变更、鉴权/敏感数据/部署操作、技术选型、任何"写代码"意图、带 summary/压缩续接的未完成任务。

禁止：未查契约直接编码；凭记忆跳过查阅；以"任务简单"为由绕过；未经用户豁免降级范围；续接复用上轮"已查"结论。

## 1. 规模分级（先分级再走流程）

调用后第一步自评并声明级别（如 `[规模: T1]`）：

| 级别 | 定义 | 典型场景 |
|------|------|----------|
| T0 | 单文件 ≤5 行，命中 §1.1 白名单且无黑名单 | 注释/空白/import 顺序/受限 typo |
| T1 | 单文件/单函数、单接口、不跨模块 | 单函数修复、单接口调参、单测补充 |
| T2 | 多文件/多接口/数据变更/跨模块 | 新增模块、表字段调整、多接口联动 |
| T3 | 架构调整/新增模块/跨系统/涉决策 | 分层引入、选型、模块拆分、部署变更 |

红线（T0/T1 命中即升 T2）：鉴权/密钥/敏感数据 → 必读 SECURITY；架构/模块边界/选型 → 必读 PROJECT+DECISION；部署/环境/CI-CD → 必读 DEPLOY。
误判：执行中发现规模超判，立即暂停按真实级别重走。

### 1.1 T0 客观判定（白名单穷举 + 黑名单硬规则 + 存疑升 T1）

T0 须同时满足：①单文件；②≤5 行（不含空行）；③变更属白名单；④无黑名单命中；⑤无红线命中；⑥已输出 §1.1.2 验证陈述。

白名单（穷举）：W1 仅注释变更；W2 仅空白/格式化（不改变 token 序列）；W3 仅 import/require 顺序重排；W4 字符串 typo（字符≤5，且不参与 URL/路径/SQL/正则/协议/鉴权/密钥/配置键/格式化模板，仅人类可读文本）。W4 无法 100% 确认用途 → 非 T0。

黑名单（任一命中即非 T0）：标识符增删改；控制流关键字变更；运算符变更；数值/布尔/null 变更；接口签名/类型/配置键/路由/权限变更；字符串变更不满足 W4；命中 SECURITY/PROJECT/DEPLOY 红线；跨文件变更。

默认升级：存疑一律按 T1，主张 T0 者负证明责任。

### 1.1.2 T0 验证陈述（主张 T0 时必须输出，缺项回退 T1）

```
[规模: T0]
文件: <路径> / 行数: <N> / 白名单: <W1-W4>
黑名单: 无（标识符/控制流/运算符/数值/接口/红线 均否）
W4 核对（如适用）: 字符<N> / 人类可读文本 / 不参与 URL/SQL/正则/路径/鉴权/密钥/配置键/模板
续接任务: 是/否（是则已按 §1.2 重跑）
```

Owner 质疑权：Owner 可随时质疑 T0 判定，agent 须立即停止并补 T1 流程，不得争辩。

### 1.2 summary 续接强制重跑（不可豁免）

任何 summary/压缩/跨会话续接，必须从 §1 重跑本 Skill，禁止"上轮已查"。
理由：压缩丢条目；续接期契约可能已被 Owner 变更；任务范围可能已扩展。
最低要求：T0 续接重读 STANDARD 相关条目 + 红线快检；T1+ 完整重走并标注"续接重查"。

## 2. 分级查阅流程

- T0：输出验证陈述 → 读 STANDARD 相关条目 → 查相关模块契约 → 红线快检 → 编码。豁免 INDEX 全量定位与 §4 表格（须一句"未涉契约更新"）。W4 完成后复核未参与禁止用途。
- T1：读 INDEX → 读 STANDARD → 读 MODULE + 相关模块契约 → 涉接口读 API → 红线快检 → 编码 → §4 自检。
- T2：定位→精读→执行。必读 INDEX/STANDARD/MODULE/相关模块契约；涉接口读 API、涉数据读 DATA、涉测试读 TEST；涉鉴权必读 SECURITY、涉决策读 DECISION。收尾 §4 全自检+PCS。
- T3：T2 全部 + 必读 PROJECT+DECISION；必读 SECURITY（无论是否涉敏感）；涉部署必读 DEPLOY；选型须先草拟 ADR 提交 Owner 审批后执行；收尾附"架构影响说明"。

## 3. 查阅映射表（T2/T3 依据）

| 任务类型 | 必读契约 |
|----------|----------|
| 任何代码编辑 | STANDARD（每次编辑前必读） |
| 不确定查哪份 | INDEX |
| 架构调整 | PROJECT |
| 接口变更 | API + 相关模块契约 |
| 定位模块 | MODULE |
| 改某模块 | modules/MODULE_XXX.md |
| 数据结构变更 | DATA + 相关模块契约（敏感字段同步 SECURITY） |
| 技术选择前 | DECISION |
| 写测试前 | TEST |
| 鉴权/敏感数据 | SECURITY（最高优先） |
| 部署/环境 | DEPLOY |
| 新建模块契约 | modules/_TEMPLATE.md |

规则：STANDARD 硬性必读；模块契约优先于全局 API/DATA；SECURITY 冲突时最高优先。

## 4. 收尾强制自检（唯一来源；契约文件不再重复声明）

> T0 一句说明即可；T1+ 必须输出表格。命中"遗漏 ❌"必须立即补更新并重新汇报。

按 INDEX §7.1 映射矩阵自检，输出：

| 契约文件 | 状态 | 备注 |
|----------|------|------|
| 文件名 | ✅已更新 / ⏭️无需更新 / ❌遗漏 | 说明 |

分级范围：Lite 只检 API/MODULE；Standard 加 DATA/DECISION；Full 检全部涉及项。

PCS（T1+ 附末尾；T0 省略）：
`📊 PCS: XX.X 分 (Lite/Standard/Full) · 模块N→X.X · 接口N→X.X · 表N→X.X · 决策N→X.X · 环境N→X.X · ⚠️跨阈值/硬触发必须显著提示并建议记入 DECISION`

监控规则：跨阈值（15/40）或硬触发（多人协作/核心业务/部署流水线/合规/高可用）必须显著提示。

## 5. 冲突优先级

SECURITY > PROJECT > STANDARD > 模块契约 > DATA > API > MODULE > DEPLOY > TEST > DECISION
冲突无法自行解决 → DECISION 记录，由 Owner 裁定。本 Skill 仅低于 SECURITY 红线。

## 6. 豁免

1. 用户明确指令跳过契约查阅（须声明"已获用户豁免"）。
2. 纯查询/解释类任务（只读不写）——可仅读相关契约。
3. 契约系统未接入的项目——先提示接入。

不可豁免：§1.2 续接重跑；安全红线。其余绕过均属违规。

## 8. 变更历史（记录在 .git）

- 变更历史以 .git 提交记录为准：每次契约变更完成后必须提交，如 `git add <文件> && git commit -m "BATCH-XXX-类型: 摘要"`。
- 语义理由（为什么这样改）同步写入 `CHANGELOG.md`（按需读，非任务必读）。
- 查询优先级：
  1. `git log --oneline -15 -- <路径>` — 最近提交摘要
  2. `git show --stat <hash>` — 单次提交改动
  3. git 不可用 → 直读 `.git/logs/HEAD`（纯文本，无需 git 程序）
  4. 语义历史 → `CHANGELOG.md`
- 若 .git 尚无提交，先完成首次提交再开始正式迭代。
- 编辑前对旧条目来龙去脉存疑时先查再动，禁止凭猜。

## 9. git 环境自检（首次运行自动安装；安装成功后本段可删）

- 任务开始前检查：`git --version`；已安装 → 跳过本段。
- 未安装 → 自动安装：
  - Windows：`winget install --id Git.Git -e --silent --accept-package-agreements --accept-source-agreements`；当前会话找不到 git 时用 `C:\Program Files\Git\cmd\git.exe`。
  - macOS：`brew install git`；Linux：`apt-get install -y git`（按发行版包管理器）。
- 安装失败（无包管理器/无管理员权限/无网络）→ 不阻塞任务，历史降级查询（§8 第 3/4 级）。
